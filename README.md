# public-api-timeseries

**保存那些「官方不留歷史」的公開數字。**

每天對一組公開端點各取一次快照，永久保存。目的不是即時查詢，而是**時間序列本身** ——
這些數字今天變了，明天就查不到昨天的值。後進者回不到過去。

## 授權
資料以 **CC BY 4.0** 釋出。使用時請標示來源。

## 為什麼這些值得存
每個來源都通過三步驗證才納入：
1. 官方是否提供歷史 API？（否）
2. Internet Archive Wayback Machine 抓得到嗎？（否，或極稀疏）
3. Hugging Face / Kaggle / GitHub 有沒有現成資料集？（否）

三項皆「否」才收錄。

## 目前兩軌

### `track-crypto/` — 加密貨幣 / AI 算力市場
| 來源 | 內容 | 為何會消失 |
|---|---|---|
| `x402_bazaar` | x402 協議全量掛牌（約 15,000 筆） | 官方 `/history` 回 404。Wayback 有 7 次擷取，但**每次僅存 100/15,122 筆（0.66%）** → 全量快照具獨佔性 |
| `cex_symbols` | 7 家交易所交易對與幣種狀態 | **本專案最具獨佔性的來源**：bybit/okx/mexc 三家 100% 只回傳存活標的（下架史遭銷毀）；僅 HTX 保留 1,547/2,159（71.7%）`offline` 紀錄 |
| `vast_gpu` | vast.ai GPU 現貨報價（512 筆） | 無官方歷史 |
| `mcp_registry` | MCP 官方註冊表（約 82,000 筆） | ⚠️ **經複核，此來源獨佔性不成立**：單日快照即含多版本、官方支援 `updated_since`、抽樣 120 筆全在線無刪除。評估中是否停止抓取 |

約 13 MB/日。

### `track-gov/` — 台灣政府公告（可問責性存檔）
| 來源 | 內容 | 為何值得存 |
|---|---|---|
| `fsc_clarification` | 金管會即時新聞澄清（全部歷史 50 筆） | 經複核修正：50 篇中 **49 篇已存在於 Wayback**（存在性冗餘）。但抽樣中位擷取數僅 **1 次**，**56% 的篇目無法用 Wayback 偵測改寫** → 每日快照對「改寫偵測」仍具獨佔性 |

**更正（2026-08-27 複核）**：原「Wayback 存檔 0 份」的測法有誤（查了網域層而非精確 URL 樣式）。
正確結論是：多數篇目**存在**於 Wayback，但擷取頻率過低（中位 1 次），無法用於偵測改寫。
本專案的價值主張因此收斂為「**高頻改寫偵測**」，而非「唯一副本」。

約 43 KB/日。每年僅新增約 5 筆。

## 這個專案不做什麼
- ❌ 不做網站、不做 API、不做儀表板
- ❌ 不做即時警報或推播
- ❌ **不做任何分析、解讀或評論**

只存原文與數字。所有詮釋留給使用者。

## 資料結構
```
<track>/data/<source>/YYYY-MM-DD.json.gz    # 一天一檔，永不覆蓋
<track>/data/_manifest/YYYY-MM-DD.json      # 當日各來源成敗、大小、耗時
<track>/scripts/                             # 抓取程式
<track>/README.md                            # 該軌的來源與技術細節
```

檔名日期為 **UTC**。

## 偵測改寫的方法
`track-gov` 每筆包含 `body_sha256`。比對相同 `dataserno` 在不同日期的 hash，
即可發現**靜默改寫**。這是本專案的核心價值 —— 不是「網站會爛掉」，而是「**沒有第三方副本**」。

## 抓取禮貌
- 每個來源**每日僅抓取一輪**。需分頁的來源會在該輪內依序請求：
  `mcp_registry` 約 827 頁、`x402_bazaar` 約 16 頁、`fsc_clarification` 約 52 次（列表 2 + 內頁 50）
- 請求間隔 1 秒
- 附帶可識別的 User-Agent
- **施工前逐一親驗 robots.txt**，明確禁止者一律排除
  （已排除：Binance、Smithery `/api/`、經濟部、Tasker、udn.com）

## 免責
本存檔僅記錄公開端點在特定時間點的回應內容，**不對資料正確性作任何保證**，
**不構成任何投資建議、法律意見或分析觀點**。使用者應自行向原始來源查證。


## 變動偵測（本專案的核心）

每日抓取後自動比對前一日快照，偵測三種事件：

| 事件 | 判斷方式 |
|---|---|
| **內容改寫** | 同一 `dataserno` 的 `body_sha256` 改變 |
| **下架** | 前一日存在、今日消失 |
| 新增 | 今日新出現 |

**只有發生「改寫」或「下架」時才留下紀錄**（單純新增不算變動事件）。

### 紀錄位置
```
CHANGES.md                              累積索引（哪幾天有變動）
changes/<source>/YYYY-MM-DD.md          當日完整 unified diff
```

### 如何得知
1. **GitHub commit 標題** — 有變動時為 `[ALERT] YYYY-MM-DD 偵測到內容改寫 N 筆、下架 M 筆`，
   平常則是 `data: YYYY-MM-DD 每日快照`。在 GitHub 按 **Watch → All Activity** 即可收到 email 通知。
2. **`CHANGES.md`** — repo 根目錄，一眼看出哪幾天出過事。
3. **`ts` 指令** — `tsdiff <source> <日期1> <日期2>` 隨時手動比對。

### diff 格式

每筆改寫皆輸出標準 unified diff，包含原始網址、`sha256` 前後對照、字數變化。
格式與 `git diff` 相同：`-` 為改寫前、`+` 為改寫後。

> 目前尚未偵測到任何改寫。本節不放範例，避免虛構內容與真實機關名稱並列造成誤解。

**本專案只陳述「內容是否被修改」此一事實，不含任何解讀或評論。**
