## 收錄判準：三步驗證

一個來源要被納入，下列三題必須**全部為「否」**：

1. 官方是否提供歷史 API 或歷史頁面？
2. Internet Archive Wayback Machine 是否已有足夠密度的擷取？
3. Hugging Face / Kaggle / GitHub 上是否已有現成資料集？

任一題為「是」，代表已有第三方副本，本專案不重複收錄。

「足夠密度」的定義：擷取頻率要能還原**逐日**變化。少數幾次擷取只能證明
「該頁曾經存在」，不能用來偵測兩次擷取之間發生的改寫。

## 逐來源查證結果

| 來源 | 官方歷史 API | Wayback 覆蓋 | 現成資料集 | 收錄 |
|---|---|---|---|---|
| `x402_bazaar` | 無（`/history` 回 404） | 7 次擷取，每次僅存 100 / 15,122 筆（0.66%） | 未發現 | 是 |
| `cex_symbols` | 無 | 不適用（API 端點） | 未發現逐日全量副本 | 是 |
| `vast_gpu` | 無 | 不適用（API 端點） | 未發現 | 是 |
| `fsc_clarification` | 無 | 50 篇中 49 篇存在，但中位擷取數為 1 次 | 未發現 | 是 |
| `mcp_registry` | **有**（官方支援 `updated_since`） | — | — | **否，已停抓** |

## 兩種不同的價值

本專案的來源分成兩類，價值主張不同，不可混談：

- **唯一副本型**（`x402_bazaar`、`cex_symbols`、`vast_gpu`）
  端點只回傳當下狀態，舊值不留任何痕跡。沒有其他已知副本。
- **高頻改寫偵測型**（`fsc_clarification`）
  頁面多數已存在於 Wayback，但擷取頻率太低。每日快照加上 `body_sha256`，
  才能偵測發布後的靜默改寫。

## 生存者偏誤

`cex_symbols` 的 7 家交易所中，bybit、okx、mexc 的 API 只回傳存活中的交易對，
下架後直接從回應消失。只有 HTX 保留 `offline` 狀態（2026-08-26 快照：1,547 / 2,159 筆）。

因此逐日快照的差集是取得下架紀錄的方式之一。萃取結果寫入
`track-crypto/data/cex_events/events.jsonl`，只記錄事件，不含任何解讀。
